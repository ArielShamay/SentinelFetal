# PRD - מסמך דרישות מוצר
## שדרוג ביצועים וחווית משתמש עבור SentinelFetal

**גרסה:** 1.0  
**תאריך:** 19 ינואר 2026  
**מחבר:** אדריכל מערכת AI  

---

## 1. סקירה כללית

### 1.1 רקע
מערכת SentinelFetal היא מערכת AI היברידית לניתוח CTG (ניטור עוברי) המשלבת:
- מודל MOMENT (Transformer Foundation Model) לחילוץ embeddings
- מנוע חוקים דטרמיניסטי לפי נייר עמדה 20 של האיגוד הישראלי
- מסווג XGBoost לקטגוריזציה סופית
- ממשק Streamlit להצגת התוצאות

### 1.2 הבעיה
המערכת הנוכחית סובלת משתי בעיות מרכזיות:

**בעיה א' - ביצועי Backend:**
- זמן inference של MOMENT על Intel i5: **2-5 שניות** לכל חלון
- המערכת "קופאת" בכל לחיצה על ניתוח
- צריכת CPU של 100% בזמן חישוב

**בעיה ב' - חווית משתמש:**
- Streamlit מריץ rerun מלא בכל אינטראקציה
- גרפים סטטיים (Matplotlib) - אין zoom/hover
- אין חיווי טעינה - המשתמש לא יודע שהמערכת עובדת

### 1.3 מטרת הפרויקט
להפוך את SentinelFetal ממערכת דמו איטית למערכת **production-ready** עם:
- **זמן תגובה < 500ms** (במקום 2-5 שניות)
- **חווית משתמש חלקה** עם גרפים אינטראקטיביים
- **יציבות** - לא קורס תחת עומס

## 3. דרישות פונקציונליות

### 3.1 שלב א' - שיפור UX מיידי (עדיפות גבוהה)

#### FR-1.1: גרפים אינטראקטיביים
- **תיאור:** החלפת Matplotlib ב-Plotly לכל הגרפים
- **פונקציונליות נדרשת:**
  - Zoom in/out על אזורים ספציפיים
  - Hover להצגת ערכים מדויקים
  - Pan לגלילה בזמן
  - Reset view לחזרה לתצוגה מקורית
- **קריטריון קבלה:** גרף CTG מגיב תוך < 100ms לכל פעולת משתמש

#### FR-1.2: חיווי טעינה (Loading States)
- **תיאור:** הוספת spinners וסרגלי התקדמות
- **פונקציונליות נדרשת:**
  - Spinner בזמן טעינת רשומה
  - Progress bar בזמן ניתוח (אם > 1 שניה)
  - הודעת סטטוס: "מעבד נתונים...", "מריץ ניתוח AI..."
- **קריטריון קבלה:** המשתמש תמיד יודע שהמערכת עובדת

#### FR-1.3: Caching אגרסיבי
- **תיאור:** שימוש ב-st.cache לכל משאב כבד
- **פונקציונליות נדרשת:**
  - `@st.cache_resource` למודלים (MOMENT, XGBoost)
  - `@st.cache_data` לתוצאות עיבוד (embeddings, rule results)
  - TTL מוגדר למניעת זיכרון אינסופי
- **קריטריון קבלה:** טעינה חוזרת של אותה רשומה < 100ms

### 3.2 שלב ב' - אופטימיזציית מודל (עדיפות גבוהה)

#### FR-2.1: המרה ל-ONNX
- **תיאור:** ייצוא מודל MOMENT מ-PyTorch ל-ONNX
- **פונקציונליות נדרשת:**
  - ייצוא המודל עם dynamic axes לתמיכה באורכי קלט משתנים
  - אימות שהפלט זהה (tolerance < 1e-5)
  - תמיכה ב-batch size של 1 (inference בודד)
- **קריטריון קבלה:** מודל ONNX מייצר embeddings זהים ל-PyTorch

#### FR-2.2: Quantization ל-INT8
- **תיאור:** כימות המודל מ-FP32 ל-INT8
- **שיטה:** Post-Training Dynamic Quantization
- **פונקציונליות נדרשת:**
  - הקטנת גודל המודל פי 4
  - האצת inference פי 2-3
  - שמירה על דיוק > 95% מהמקור
- **קריטריון קבלה:** F1-score יורד ב-< 2% לעומת FP32

#### FR-2.3: OpenVINO Integration
- **תיאור:** המרה ל-OpenVINO IR להאצה על Intel CPU
- **פונקציונליות נדרשת:**
  - המרה מ-ONNX ל-OpenVINO IR (.xml + .bin)
  - שימוש ב-openvino.runtime לטעינה והרצה
  - תמיכה ב-CPU Plugin עם אופטימיזציות אוטומטיות
- **קריטריון קבלה:** Inference time < 500ms על Intel i5

### 3.3 שלב ג' - שיפורים מתקדמים (עדיפות בינונית)

#### FR-3.1: Embedding Caching
- **תיאור:** שמירת embeddings מחושבים למניעת חישוב חוזר
- **פונקציונליות נדרשת:**
  - Cache מבוסס record_id + window_index
  - שמירה בזיכרון (dict) או בקובץ (pickle/numpy)
  - Invalidation אוטומטי אם המודל משתנה
- **קריטריון קבלה:** ניתוח חוזר של אותה רשומה < 50ms

#### FR-3.2: Lazy Loading
- **תיאור:** טעינת מודלים רק כשצריך אותם
- **פונקציונליות נדרשת:**
  - טעינת XGBoost מיידית (קל)
  - טעינת MOMENT רק בלחיצה על "ניתוח מלא"
  - הודעה למשתמש: "טוען מודל AI לראשונה..."
- **קריטריון קבלה:** זמן טעינת דף ראשונית < 1 שניה

#### FR-3.3: Background Processing (אופציונלי)
- **תיאור:** חישוב embeddings ברקע
- **פונקציונליות נדרשת:**
  - התחלת חישוב מיד לאחר בחירת רשומה
  - הצגת תוצאות חלקיות (גרף, baseline) תוך כדי
  - עדכון קטגוריה כשה-AI מסיים
- **קריטריון קבלה:** תחושת תגובה מיידית למשתמש

## 4. דרישות לא-פונקציונליות

### 4.1 ביצועים (Performance)
- **NFR-1:** Inference latency < 500ms על Intel i5 Gen 11+
- **NFR-2:** Memory footprint < 2GB total
- **NFR-3:** Cold start < 5 שניות (כולל טעינת מודלים)

### 4.2 תאימות (Compatibility)
- **NFR-4:** Python 3.10+
- **NFR-5:** פועל על Windows/Linux/macOS
- **NFR-6:** תואם לחומרה ללא GPU (Intel CPU only)

### 4.3 אמינות (Reliability)
- **NFR-7:** אין crash בזמן inference
- **NFR-8:** Graceful degradation אם מודל לא נטען
- **NFR-9:** שמירה על דיוק קליני לאחר quantization

### 4.4 תחזוקה (Maintainability)
- **NFR-10:** קוד מתועד עם docstrings
- **NFR-11:** הפרדה ברורה בין מודולים
- **NFR-12:** בדיקות יחידה לפונקציות קריטיות

## 5. אילוצים וסיכונים

### 5.1 אילוצים
| אילוץ | תיאור | השלכה |
|-------|-------|-------|
| חומרה | Intel i5 ללא GPU | חייב להשתמש ב-CPU optimizations |
| רגולציה | נייר עמדה 20 | חייב לשמור על מנוע חוקים דטרמיניסטי |
| Pure Python | דרישת לקוח | לא ניתן לכתוב C extensions |
| Streamlit | ממשק קיים | נשאר עם Streamlit, לא עוברים ל-React |

### 5.2 סיכונים
| סיכון | סבירות | חומרה | מיטיגציה |
|-------|---------|--------|----------|
| Quantization פוגע בדיוק | בינונית | גבוהה | בדיקת F1 לפני ואחרי |
| OpenVINO לא תואם | נמוכה | גבוהה | fallback ל-ONNX Runtime |
| זיכרון לא מספיק | נמוכה | בינונית | Lazy loading |
| Streamlit bottleneck | בינונית | בינונית | Async processing |
